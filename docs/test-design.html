Context-First Test Design

Test cases are now designed from the module context that the context-builder writes, not one gap at a time. The draft stage first writes the full set of tests the module should have. Then it checks each one against the existing Zephyr cases and drafts only the ones nobody covers. Every gap says which rule or workflow needs it and why no existing case tests it.

New flow

Scope, the four explorers and the context-builder are unchanged. The work happens inside the draft stage, before the test-designer agent starts: three Claude calls that the orchestrator runs as script steps.

An illustrative case for grid export, built from the shape the design and check calls return. The second half is what the check adds. A Missing or Partial result becomes a row in 9_Gaps, and its reason text joins the two halves.

Rules a change must keep

  • Zephyr has no delete endpoint. Cases are created only through create-approved (dry run, then --yes) after explicit approval.
  • No Jira comments or issue changes during an analysis.
  • Agents change state only through their own review file, never state.json or the workbook.
  • Every designed case carries a whyNeeded and a check reasoning; the workbook build rejects rows without them.
  • Report tokens only, never cost.
